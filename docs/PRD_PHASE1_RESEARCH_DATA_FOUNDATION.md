# 第一阶段 PRD：运动训练科研数据基础与可信分析

| 项目 | 内容 |
|---|---|
| 产品名称 | 运动训练科研数据分析与报告系统 |
| 阶段 | Phase 1：数据基础与可信分析 |
| 文档版本 | v1.0 |
| 目标读者 | 产品负责人、开发人员、测试人员、执行型 AI Agent |
| 部署方式 | Windows 本地部署，数据默认不出网 |
| 当前技术栈 | Next.js 15、React 19、ECharts 5、FastAPI、SQLAlchemy、PostgreSQL/SQLite |

## 1. 产品定位

本阶段将现有系统收敛为一个面向运动训练科研人员的本地数据管理与统计分析工具。

系统必须完成从原始数据导入到可复核科研结果的闭环：

```text
原始文件 → 字段映射 → 数据质量检查 → 人工确认 → 正式数据集
        → 描述统计 → 纵向/组间/相关分析 → 科研图表 → 结果导出与追溯
```

本阶段不建设综合运动队管理平台，不承诺医学诊断、伤病预测或自动训练处方。

## 2. 背景与问题

当前数据来自 Excel、CSV、设备导出文件和人工整理结果，存在以下问题：

- 字段名称、单位和编号规则不统一；
- 数据、代码、数据库及报告产物混放；
- 导入错误仅以简单文本返回，缺少可操作的数据质量报告；
- 缺少完整的数据来源、修订历史和分析版本记录；
- 统计结果偏重 p 值，缺少效应量、置信区间和适用条件说明；
- 多种数据源和多个数据库并存，正式数据源不明确；
- 分析结果难以稳定复现并批量生成报告。

## 3. 阶段目标

### 3.1 核心目标

1. 建立统一、可扩展的数据字典和指标体系。
2. 建立标准化、可预览、可复核的数据导入流程。
3. 建立自动数据质量检查与修正记录。
4. 建立可复现的基础科研统计分析模块。
5. 建立统一的科研图表和结果导出能力。
6. 保证每个分析结果能够追溯到数据版本和分析参数。

### 3.2 成功指标

- 标准模板导入成功率 ≥ 95%；
- 重复、缺失、单位冲突和非法值的测试检出率 = 100%；
- 同一数据版本和分析配置重复运行结果完全一致；
- 核心统计结果与独立 Python 验证脚本一致；
- 用户可在 10 分钟内完成一次标准数据导入、检查和确认；
- 用户可在 5 分钟内生成一份标准科研分析结果；
- 导出结果包含样本量、单位、方法、参数、生成时间和版本信息。

## 4. 用户与使用场景

### 4.1 核心用户

- 体育科研教师；
- 科研助理和研究生；
- 运动队科研保障人员；
- 数据分析人员。

### 4.2 本阶段权限

仅保留两种业务权限：

- 数据维护者：导入、修正、确认和删除批次；
- 分析使用者：查看正式数据、运行分析和导出结果。

现有管理员、教练、运动员角色代码可以保留，但不继续扩展相关业务功能。

### 4.3 核心场景

1. 用户导入一份三时间点血液检测数据。
2. 系统检查字段、单位、编号、重复、缺失及异常值。
3. 用户在预览页逐项确认问题，并形成正式数据版本。
4. 用户选择指标、组别和时间点，运行描述统计或假设检验。
5. 系统生成统计表、科研图表和方法说明。
6. 用户导出 Excel、PNG/SVG 和结构化分析结果。
7. 用户能够在未来重新打开该分析，并获得相同结果。

### 7.2 数据原则

- 正式数据库是唯一事实来源；
- 原始文件只读保存，不直接覆盖；
- 导入预览数据不得进入正式分析；
- 所有单位在写入正式观察表前转换为标准单位；
- 所有人工修订必须记录原值、新值、原因和时间；
- 所有分析必须绑定不可变的数据版本；
- 姓名不是数据关联键，运动员编码才是关联键。

参考区间不得只记录数值，必须同时记录来源、适用人群和版本日期。

## 9. 功能需求

### FR-01 项目管理

- 创建、编辑、归档科研项目；
- 设置研究设计、组别和时间点；
- 项目之间的数据默认隔离；
- 项目归档后只读，不允许新增数据。

验收：创建两个项目时，同一运动员编码可以分别存在，数据不会互相出现在分析中。

### FR-02 标准导入模板

- 提供可下载 XLSX/CSV 模板；
- 模板包含字段说明、示例、单位和必填标记；
- 模板版本必须写入文件；
- 支持宽表和规范长表，系统内部统一转换成长表；
- 不支持的模板必须给出明确错误，不得静默导入。

### FR-03 导入预览和字段映射

- 上传后先预览前 50 行；
- 自动识别常见中文、英文和历史字段名；
- 用户可以手动修改字段映射；
- 显示原单位与目标标准单位；
- 显示预计新增、更新、重复和拒绝记录数；
- 用户确认前不得写入正式观察表。

### FR-04 数据质量规则

必须实现以下规则：

| 规则 | 严重程度 | 行为 |
|---|---|---|
| 缺少运动员编码 | error | 阻止该行确认 |
| 未知指标 | error | 阻止该指标确认 |
| 非法日期/时间点 | error | 阻止该行确认 |
| 非数字检测值 | error | 阻止该值确认 |
| 未知或不可换算单位 | error | 阻止该值确认 |
| 完全重复记录 | warning | 默认跳过 |
| 可能重复记录 | warning | 要求人工选择 |
| 超出合理范围 | warning | 人工确认后可保留 |
| 缺失非必填值 | info | 允许确认 |
| 低于检测下限 | info | 按指标规则保存 qualifier 和 LOD |
| 时间点缺失 | warning | 允许导入，分析时提示 |
| 组别样本不平衡 | warning | 允许导入，分析时提示 |

质量报告必须显示总记录、错误、警告、信息、可分析率和问题分布。

### FR-05 问题处理

- 可按严重程度、规则、字段和行筛选问题；
- 可以接受建议值、手动修正、忽略警告或拒绝记录；
- error 未解决时不得确认批次；
- 每次处理写入审计记录；
- 批次确认后支持整体回滚，不允许部分静默删除。

### FR-06 数据版本

- 每次批次确认生成新的数据版本号；
- 数据人工修订生成新的次版本；
- 已完成的分析继续绑定旧版本；
- 用户可以比较两个数据版本的新增、删除和修改记录。

建议格式：`project-slug/YYYYMMDD.major.minor`。

### FR-07 描述统计

支持按指标、时间点、组别和性别分层，输出：

- 有效样本量和缺失量；
- 均值、标准差；
- 中位数、Q1、Q3、IQR；
- 最小值、最大值；
- 95% 置信区间；
- 异常值数量；
- 检测下限值数量；
- 使用的单位和数据版本。

### FR-08 纵向分析

首期支持：

- Friedman 检验；
- Wilcoxon 配对检验；
- Holm 多重比较校正；
- 配对样本量；
- 中位数变化和百分比变化；
- 配对效应量；
- 效应量 95% 置信区间；
- 完整案例与可用案例数量说明。

二级接口预留线性混合效应模型，不在本次强制实现。

### FR-09 组间分析

首期支持：

- Kruskal-Wallis 检验；
- 显著时执行预定义的组间事后比较；
- 事后检验多重校正；
- 每组样本量；
- 组间效应量；
- 效应量 95% 置信区间；
- 样本不平衡提示。

### FR-10 相关分析

- 支持 Spearman 相关；
- 显示 ρ、p、样本量 n 和 95% 置信区间；
- 支持选择时间点、组别和指标；
- 支持多重检验校正；
- 缺失值处理方式必须显示；
- 图表和结果页必须显示“相关不等于因果”。

首期不提供自动因果结论。

### FR-11 科研图表

必须提供：

- 个体轨迹图；
- 组别分布箱线图叠加原始点；
- 纵向变化小多图或相对指数图；
- 显著性矩阵；
- 相关矩阵；
- 散点图及趋势线；
- 数据质量概览图。

图表规范：

- 每张图只表达一个主要问题；
- 显示标题、单位、样本量和数据版本；
- 不同单位的指标不得共用同一数值轴；
- 不使用 3D 图；
- 不使用多分类饼图；
- 不单独用颜色传递显著性；
- 支持色觉缺陷辨识；
- 核心数值不得只能通过 hover 获取；
- 图表导出后仍应包含标题、单位和注释。

### FR-12 分析方案与复现

- 用户可以保存分析名称和配置；
- 配置包括项目、数据版本、筛选条件、指标、分组、时间点、统计方法和校正方式；
- 再次运行相同配置必须得到相同结果；
- 若选择新数据版本，必须创建新的 AnalysisRun，不得覆盖旧结果；
- 结果页显示软件版本和运行时间。

### FR-13 导出

首期支持：

- 原始筛选数据 CSV；
- 描述统计和检验结果 XLSX；
- 分析配置和结果 JSON；
- 图表 PNG 和 SVG；
- 数据质量报告 HTML 或 PDF。

每个导出包必须包含 `manifest.json`，记录项目、数据版本、分析版本、文件清单、生成时间和 SHA256。

### FR-14 备份与恢复

- 提供本地数据库备份命令或界面；
- 备份包含数据库、原始文件索引、数据字典和版本信息；
- 恢复前自动校验备份完整性；
- 文档必须说明备份路径、恢复步骤和失败处理；
- 测试环境必须至少完成一次备份恢复演练。

## 10. 统计规范

### 10.1 通用规则

- 分析前显示纳入和排除记录数；
- 不自动用均值或零填补缺失值；
- 不把低于检测限的数据简单当作零；
- 同一运动员重复测量不得当作独立样本；
- 所有 p 值同时报告效应量和样本量；
- 多指标、多组别或多时间点检验必须说明校正方法；
- 结果保留足够精度，界面格式化不得改变底层值；
- 统计函数必须固定随机种子（如涉及 bootstrap）；
- 结果 JSON 中保留未格式化数值。

### 10.2 置信区间

- 明确置信区间算法；
- bootstrap 默认至少 2,000 次重采样；
- 固定并记录随机种子；
- 样本量不足时返回明确状态，不输出伪精确区间。

### 10.3 结果语言

允许：

- “当前样本显示……”；
- “观察到统计关联……”；
- “未发现足够证据支持组间差异……”；
- “结果受样本量限制……”。

禁止自动生成：

- “该方案一定有效”；
- “该运动员存在医学风险”；
- “该指标导致成绩变化”；
- “系统建议停止训练”。

## 12. 非功能需求

### 12.1 隐私与安全

- 默认不访问互联网；
- 不在日志中记录密码、完整姓名或检测原始文件内容；
- 导出默认使用运动员编码；
- 敏感配置通过环境变量提供；
- JWT 密钥和数据库密码不得硬编码；
- 原始文件、数据库和备份必须有明确存储位置；
- 任何未来云端 OCR 必须作为独立可关闭模块，不属于本阶段。

### 12.2 性能

- 10 万条观察记录的筛选响应目标 ≤ 2 秒；
- 1 万行标准文件的质量检查目标 ≤ 10 秒；
- 常规基础统计运行目标 ≤ 5 秒；
- 长任务必须显示进度或明确运行状态。

### 12.3 可用性

- 错误信息必须说明原因和解决办法；
- 空状态必须提供下一步操作；
- 表格支持筛选、排序和分页；
- 页面支持 1280px 桌面和 768px 平板宽度；
- 关键操作支持键盘焦点和可访问标签。

### 12.4 可维护性

- Python 和 JavaScript 依赖锁定版本；
- 数据库结构使用迁移工具管理；
- 统计逻辑与 API 路由分离；
- 数据转换与图表配置分离；
- 不允许在页面组件内复制统计计算；
- 新增指标不得要求修改多个页面的硬编码列表。

## 13. 测试要求

### 13.1 单元测试

- 单位换算；
- 日期和时间点解析；
- 重复记录识别；
- 检测下限处理；
- 每条数据质量规则；
- 描述统计；
- Friedman、Wilcoxon、Kruskal-Wallis、Spearman；
- 多重比较校正；
- 效应量和置信区间；
- 分析配置哈希和复现。

### 13.2 集成测试

- 上传—校验—修正—确认完整流程；
- error 未解决时确认失败；
- 批次回滚；
- 数据版本差异；
- 相同配置重复运行结果一致；
- 权限限制；
- 导出包 manifest 和哈希校验；
- 备份恢复。

### 13.3 前端测试

- 导入映射交互；
- 问题筛选和修正；
- 空数据、错误和加载状态；
- 图表单位和标题；
- 导出触发；
- 768px 与 1280px 页面布局；
- 不同单位指标不会出现在同一原始数值轴。

### 13.4 统计黄金数据集

仓库内建立不含真实个人信息的小型合成数据集，并保存经独立工具确认的期望结果。

每次修改统计模块时，必须对黄金数据集执行回归测试。

## 17. 执行型 AI 工作规则

交给其他 AI Agent 执行时，必须遵守：

1. 先读取本 PRD、项目 README、现有数据库模型和 API，不得直接重写整个项目。
2. 保留用户现有修改，不得执行 `git reset --hard` 或删除未知文件。
3. 每个里程碑单独提交设计说明、数据库变更和验收结果。
4. 数据库变更必须通过迁移完成，不得只修改 ORM 模型。
5. 统计实现必须先添加黄金数据集测试，再接入 API 和前端。
6. 不得为简化实现而把缺失值填零或删除全部不完整个体。
7. 不得改变现有统计口径而不记录迁移说明。
8. 不得上传真实运动员数据到外部服务。
9. 不得扩展本阶段明确排除的功能。
10. 每完成一个里程碑，运行后端测试、前端测试和生产构建。
11. 若 PRD 与现有数据含义冲突，停止相关字段实施并生成冲突清单，不得自行猜测。
12. 最终交付必须列出：已完成项、未完成项、测试证据、数据迁移方法、已知风险和下一步建议。
